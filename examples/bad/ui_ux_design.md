# UI/UX 设计反例 | Bad Examples

常见UI/UX设计错误案例，以及如何改进。

---

## 按钮设计

### ❌ 错误示例：混乱的层级与模糊的交互

**问题：**
- 所有按钮使用相同的视觉样式，无法区分主次
- 没有hover/focus/active状态反馈
- 禁用状态与普通状态无区分
- 点击区域过小（<44x44px）

**反例：**
```
┌──────────────┐
│    按钮A     │  ← 所有按钮看起来一样
├──────────────┤
│    按钮B     │
├──────────────┤
│    按钮C     │
└──────────────┘
```

**改进方案：**
```
主按钮：填充色 + 明显圆角 + hover放大
次按钮：描边 + 较轻颜色
辅助按钮：ghost样式 + 最小视觉权重
```

## 表单设计

### ❌ 错误示例：标签混乱与错误处理不当

**问题：**
- 标签与占位符混用
- 错误提示位置不明确或过于技术化
- 必填项无标记
- 输入框过窄无法完整显示内容

**反例：**
```
┌─────────────────────┐
│ 输入邮箱地址         │ ← 占位符替代标签
└─────────────────────┘
Error: INVALID_FORMAT ← 技术性错误，无帮助
```

**改进方案：**
```
邮箱地址 *
┌─────────────────────┐
│ 请输入邮箱地址       │ ← 标签清晰
└─────────────────────┘
✗ 请输入有效的邮箱格式，如：user@example.com
```

## 导航设计

### ❌ 错误示例：信息过载与歧义

**问题：**
- 导航项超过7个
- 使用模糊的导航标签（"更多"、"其他"）
- 无当前页面指示
- 下拉菜单层级过深（>3层）

**反例：**
```
首页 | 产品 | 关于 | 服务 | 解决方案 | 案例 | 新闻 | 招聘 | 联系 | 更多
                                                                         ↑
                                                                   什么在这里？
```

**改进方案：**
```
使用下拉菜单分组 + 最多7个顶层项 + 清晰的当前页标识
```

## 卡片设计

### ❌ 错误示例：视觉不一致与内容过载

**问题：**
- 卡片大小不一，破坏网格
- 内容堆叠过密，无呼吸感
- 标题过长被截断
- CTA按钮位置不一致

**反例：**
```
┌─────────────┐  ┌─────────────┐
│ 图 │ 产品A长名称│ │产品B│
│   │描述文字    │ │描述文字描述│
│   │[操作] [详情]│ │  [操作]   │
└─────────────┘  └─────────────┘
  ↑尺寸不一     ↑按钮位置混乱
```

**改进方案：**
```
统一卡片尺寸 + 网格对齐 + 一致的CTA位置 + 标题截断处理
```

## 空状态设计

### ❌ 错误示例：空白与冷漠

**问题：**
- 纯空白，无任何引导
- 错误信息冷漠或指责
- 无任何操作入口

**反例：**
```
(empty)

No data available.
```

**改进方案：**
```
插图 + 友好文案 + 明确的下一步行动按钮
```

## 加载状态

### ❌ 错误示例：无尽等待

**问题：**
- 仅有spinner，无进度提示
- 长时间加载无取消选项
- 加载失败无重试入口

**反例：**
```
[ ○ ] ← spinner，无上下文
```

**改进方案：**
```
骨架屏 + 进度条 + 取消按钮 + 失败重试
```

## 错误处理

### ❌ 错误示例：技术术语与无用提示

**问题：**
- 使用技术性错误代码
- 错误信息模糊（如"发生错误"）
- 不提供解决建议
- 强制刷新页面丢失用户数据

**反例：**
```
Error: 0x80070005
Access Denied

[确定] ← 点击后返回空白页，用户数据丢失
```

**改进方案：**
```
友好的错误描述 + 具体解决步骤 + 保留用户输入 + 便捷的重试
```

## 移动端设计

### ❌ 错误示例：拇指盲区

**问题：**
- 高频操作放在屏幕顶部
- 可点击目标过小（<44px）
- 边缘手势与系统操作冲突
- 底部导航缺少指示

**反例：**
```
┌─────────────────────┐
│ [操作] [操作] [操作] │ ← 所有操作在顶部
│                     │
│     内容区域         │
│                     │
│                     │
└─────────────────────┘
  ↑ 无底部导航
```

**改进方案：**
```
高频操作放底部 + 最小点击区域48x48dp + 清晰的底部导航
```

## 颜色使用

### ❌ 错误示例：颜色滥用

**问题：**
- 仅用颜色传递信息（色盲用户无法识别）
- 对比度不足（WCAG AA要求4.5:1）
- 错误状态仅用红色（红绿色盲问题）
- 背景与文字对比度过低

**反例：**
```
浅灰文字 #CCCCCC on 白色背景 #FFFFFF → 对比度 1.6:1 ❌
纯红 #FF0000 表示错误（色盲无法识别）
仅用颜色区分：绿色=成功，红色=失败
```

**改进方案：**
```
使用图标+颜色组合 + 对比度≥4.5:1 + 文字标签辅助
```
