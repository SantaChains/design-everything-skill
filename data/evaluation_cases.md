# 评测三层体系 Evaluation Framework v2.0

本文档定义 design-everything skill 的三层评测体系，用于验证 skill 的正确性和有效性。

---

## 评测体系总览

```
┌─────────────────────────────────────────────────────────────┐
│                    L3: 输出验证 (端到端)                      │
│  指标: 用户满意度 >= 85%, 格式合规率 100%                      │
├─────────────────────────────────────────────────────────────┤
│                    L2: 流程验证 (StateGraph)                  │
│  指标: 阶段完成率 >= 95%, 平均质量分 >= 80                     │
├─────────────────────────────────────────────────────────────┤
│                    L1: 触发验证 (元数据)                       │
│  指标: 触发准确率 >= 90%                                      │
└─────────────────────────────────────────────────────────────┘
```

---

## L1: 触发验证层

### 目标
验证 Skill 的触发机制是否准确，包括正向激活和负向排除。

| L1-P06 | "赛博朋克风格的特征" | ✅ 触发 | 包含风格关键词 |

- **误触发率** < 10%

## L2: 流程验证层

### 目标
验证 StateGraph 工作流的正确执行，包括状态转换、Checkpoint 验证和错误恢复。

### 测试用例

#### 状态转换测试

| ID | 场景 | 预期路径 | 验证点 |
|----|------|----------|--------|
| L2-T01 | 完整工作流 | ANALYZE→PROPOSE→COLOR→LAYOUT→ELEMENTS→AVOID→COMPLETE | 7 阶段顺序执行 |
| L2-T02 | 信息不足 | ANALYZE→(Inversion)→ANALYZE→PROPOSE... | 触发反转模式 |
| L2-T03 | 用户拒绝风格 | PROPOSE→(返回)→ANALYZE→PROPOSE... | 回退机制 |
| L2-T04 | 对比度不满足 | COLOR→(调整)→COLOR→LAYOUT... | 自动修复 |

#### Checkpoint 验证测试

| ID | 阶段 | Checkpoint 检查项 | 预期结果 |
|----|------|-------------------|----------|
| L2-C01 | ANALYZE | 关键词>=3, 情绪确定, 场景明确 | quality_score >= 0.8 |
| L2-C02 | PROPOSE | 2-3种风格, 有特征, 用户确认 | quality_score >= 0.8 |
| L2-C03 | COLOR | 主/辅/点缀色, HEX值, 理由 | quality_score >= 0.8 |
| L2-C04 | LAYOUT | 构图法则, 视觉层级, 布局描述 | quality_score >= 0.8 |
| L2-C05 | ELEMENTS | 元素列表, 作用说明, 优先级 | quality_score >= 0.8 |
| L2-C06 | AVOID | 禁忌事项, 原因, 替代方案 | quality_score >= 0.8 |

#### 错误恢复测试

| ID | 场景 | 触发条件 | 预期行为 |
|----|------|----------|----------|
| L2-E01 | 阶段失败 | quality_score < 0.5 | 自动重试 (最多3次) |
| L2-E02 | 重试失败 | 重试3次后仍失败 | 回退到上一阶段 |
| L2-E03 | 用户中断 | 用户说"重新开始" | 返回 ANALYZE |
| L2-E04 | 分支实验 | 用户说"试试另一个风格" | 从 PROPOSE 创建分支 |

### 通过标准
- **阶段完成率** >= 95%
- **平均质量分** >= 80
- **错误恢复成功率** >= 90%

## L3: 输出验证层

### 目标
验证最终输出的质量和用户满意度。

### 测试用例

#### 端到端场景测试

| ID | 场景 | 输入 | 预期输出 | 验证点 |
|----|------|------|----------|--------|
| L3-E01 | 科技感配色 | "设计一个科技感的配色方案" | 完整 7 阶段输出 | 格式合规, 色值正确 |
| L3-E02 | 品牌设计 | "设计一个奢侈品牌的视觉系统" | 完整输出 + 品牌建议 | 专业性, 完整性 |
| L3-E03 | UI 组件 | "设计一个登录表单" | 完整输出 + 组件规范 | 可执行性 |
| L3-E04 | 游戏场景 | "设计一个赛博朋克游戏场景" | 完整输出 + 场景描述 | 风格一致性 |
| L3-E05 | 视频剪辑 | "剪辑一个产品宣传视频" | 完整输出 + 剪辑建议 | 专业性 |

#### 格式合规测试

| ID | 检查项 | 要求 |
|----|--------|------|
| L3-F01 | 阶段标识 | 每个阶段有明确的 [阶段: XXX] 标识 |
| L3-F02 | Checkpoint 显示 | 每个阶段有 Checkpoint: ✅/❌ + score |
| L3-F03 | 色值格式 | HEX 格式 (#XXXXXX) |
| L3-F04 | 完整性 | 7 个阶段全部完成 |
| L3-F05 | 总质量分 | 输出总质量分 |

#### 用户满意度测试

| ID | 评估维度 | 目标值 |
|----|----------|--------|
| L3-S01 | 专业性 | >= 4.0/5.0 |
| L3-S02 | 完整性 | >= 4.0/5.0 |
| L3-S03 | 可执行性 | >= 4.0/5.0 |
| L3-S04 | 风格一致性 | >= 4.0/5.0 |
| L3-S05 | 整体满意度 | >= 85% |

### 通过标准
- **用户满意度** >= 85%
- **格式合规率** 100%
- **端到端成功率** >= 90%

## 自动化评测流程

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  L1 触发测试 │────→│  L2 流程测试 │────→│  L3 输出测试 │
└─────────────┘     └─────────────┘     └─────────────┘
       │                   │                   │
       ↓                   ↓                   ↓
  触发准确率          阶段完成率           用户满意度
  误触发率            平均质量分           格式合规率
  漏触发率            恢复成功率           端到端成功率
       │                   │                   │
       └───────────────────┼───────────────────┘
                           ↓
                    ┌─────────────┐
                    │  质量报告    │
                    └─────────────┘
```

### CI/CD 集成

```yaml
# .github/workflows/eval-skill.yml
name: Skill Evaluation
on: [push, pull_request]

jobs:
  evaluate:
    runs-on: ubuntu-latest
    steps:
      - name: L1 Trigger Test
        run: python scripts/eval_l1_trigger.py
        
      - name: L2 Workflow Test
        run: python scripts/eval_l2_workflow.py
        
      - name: L3 Output Test
        run: python scripts/eval_l3_output.py
        
      - name: Generate Report
        run: python scripts/generate_eval_report.py
```

## 迭代闭环

### 评测失败处理流程

```
评测失败
    │
    ├── L1 失败 → 分析触发问题
    │              ├── 修改 frontmatter
    │              └── 调整关键词覆盖
    │
    ├── L2 失败 → 分析流程问题
    │              ├── 修改 StateGraph 定义
    │              ├── 调整 Checkpoint 条件
    │              └── 优化 Error Handling
    │
    └── L3 失败 → 分析输出问题
                   ├── 修改输出模板
                   ├── 优化内容质量
                   └── 调整风格一致性
```
